## 3. 测试环境要求

1. **NAS 侧**
   - 已开启 WebDAV（代码按目标 NAS 的 WebDAV 行为编写：`PROPFIND` 返回 207、`MOVE` 跨挂载点返回 405）。
   - 提供**两个不同存储池**的路径（跨盘用例必需）。
   - 用于测试的目录必须**可写**：`MOVE` / `COPY` / `DELETE` / `MKCOL` / `PUT`（`PUT` 用于写 `snap-config.json`）。
2. **浏览器侧**
   - 手机浏览器：Android Chrome / Edge（主力），iOS Safari（能力受限，见 FS 模块）。
   - 页面必须从 **WebDAV 的完整文件地址**打开：`http://192.0.2.10:5005/pool-a/snap-test/index.html`。
     打开目录地址只会看到 WebDAV 自带文件列表，不会加载应用（部署脚本也会这么提示）。
   - 应用**自身不弹登录框**：所有请求都带 `credentials:'same-origin'`，依赖浏览器已缓存该 origin 的 Basic 凭据。
     首次打开时由浏览器原生弹窗输入 `ACCOUNT` / 密码；**测 401 用例时需要能清掉这份缓存凭据**。
   - 手机与 NAS 在同一局域网内。
3. **桌面浏览器**（KBD 模块）
   - Chrome / Edge 桌面版，打开同一地址（WebDAV 下 Fullscreen API 与键盘事件均可用）。
4. **辅助工具**
   - `curl`、`python3`（`tools/deploy-webdav.sh` 依赖；`python3` 用于 URL 编码）。
   - 建议准备一个能在 WebDAV 上直接放/取文件的方式（浏览器或 `curl -u ACCOUNT -T`），用于**造数据和恢复配置**。

### 3.1 部署到测试目录

部署脚本用法（读自 `tools/deploy-webdav.sh` 头部注释与实现，未编造参数）：

```bash
# 部署单文件到指定完整远端路径
bash tools/deploy-webdav.sh public/index.html /pool-a/snap-test/index.html

# 上传整个目录（递归；脚本会对子目录发 MKCOL）
bash tools/deploy-webdav.sh public/ /pool-a/snap-test/

# 用环境变量给目标根目录
DAV_ROOT=/pool-a/snap-test bash tools/deploy-webdav.sh public/
```

脚本的真实行为（测试前需知道）：

- 凭据从仓库根目录的 `.nas-cred` 读取，支持 `NAS_USER=xxx` / `username: xxx` 两种写法；也识别 `NAS_PASS` / `NAS_HOST` / `WEBDAV_PORT`。凭据**不通过命令行参数传递**，该文件不入库。
- `NAS_HOST` 必须在 `.nas-cred` 里给（脚本里写死了「真实地址不入库，所以不写在脚本里」），端口 `WEBDAV_PORT` 默认 `5005`。
- 第二个参数若以 `/` 结尾（或省略，用 `DAV_ROOT`）→ 视为目录，沿用本地文件名；否则视为**完整远端文件路径**。
- 第二个参数可以直接粘贴完整的 `http(s)://host:port/...` URL，脚本会自动剥掉 `http(s)://host[:port]`。
- 上传走 HTTP `PUT`；**目标目录本身不会被自动创建**，需要事先在 NAS 上（或文件管理器里）建好 `/pool-a/snap-test/`。
- 脚本结束会打印可直接在手机打开的**完整文件地址**。

> 因为 `snap-config.json` 写在**页面所在目录**，把应用部署到 `/pool-a/snap-test/` 就等于自带一份独立配置
> （`/pool-a/snap-test/snap-config.json`）。这是本用例集最重要的隔离手段。

## 4. 测试数据的准备与清理原则（重要）

### 4.1 配置是「共享的单份」

- 应用只有**一份**配置：`snap-config.json`，位于应用页面所在目录，**同一目录下所有设备/浏览器共享**。
  代码注释写明：「换设备/换浏览器/清缓存都能沿用」。
- 配置内容包含：`source`、`targets`（20 项）、`del`、`filter`、`autoplay`、`autoFs`、`sort`、`undo`（最多 50 条）、`version`、`updated`。
- 因此：**任何一次「设置」「筛选切换」「排序切换」「自动播放开关」「分类移动」都会在 500ms 防抖后 PUT 覆盖这份文件**（含撤销栈）。

**铁律：**

1. 测试前把 `/pool-a/snap-test/snap-config.json` 原样备份（例如另存为 `/pool-a/snap-test/snap-config.json.bak` 或存到本地）。
2. 测试结束（或中途需要干净状态时）用备份**原样 PUT 回去**；不要在测试目录里留下被改脏的配置。
3. **绝对不要**把真实的工作目录配进去做破坏性操作（移动、删除）。破坏性用例只允许在 `/pool-a/to-sort/`、`/pool-a/target-*`、`/pool-b/target-x/`、`/pool-a/discard/` 这些一次性目录里做。
4. 每个大模块开始前记录一次配置内容（或截图设置面板），便于判断「是谁改了配置」。
5. 配置没恢复就会影响其它人/其它设备：测试环境建议使用一个**专门的部署目录**（如 `/pool-a/snap-test/`），不要用日常在用的那个目录。

### 4.2 测试数据目录

```

/pool-a/target-a/           ← 目标（同盘）                             【可丢弃】
/pool-a/target-b/           ← 目标（同盘）                             【可丢弃】

/pool-a/discard/            ← 丢弃目录                                 【可丢弃】
/pool-b/target-x/           ← 目标（另一块盘，跨盘用例）                【可丢弃】
```

| --- | --- |

## 6. 冒烟用例

**SMK-01 · 页面能完整加载**
- **优先级**：P0
- **前置条件**：已部署到 `/pool-a/snap-test/index.html`，浏览器已有该 origin 的凭据。
- **步骤**：1) 打开 `http://192.0.2.10:5005/pool-a/snap-test/index.html`；2) 等待加载完成；3) 打开浏览器控制台看有无报错。
- **预期结果（界面）**：顶栏从左到右为 `📂` 源按钮（无配置时显示 `未选择待分类目录` + `点这里选择`）、媒体类型 chip（初始 `图+视`）、`▦` 图集按钮、`⛶` 全屏按钮；主区显示 `🖼️ 先选一个「待分类」目录 / 然后在下面配置目标目录`；底部是 20 个槽位（编号 1–20，全部虚线框、显示 `未设置`）与三个按钮 `↶ 撤销`（置灰）、`🗑 丢弃`、`⚙ 设置`。
- **预期结果（WebDAV 侧）**：无写操作；无配置时首页会列出**应用自身所在目录**的内容（默认浏览 `location.pathname` 所在目录）。
- **备注**：`openSource` 的兜底起点是页面所在目录，因此首页可能看到 `index.html`；这是预期行为。

**SMK-02 · 一条完整主流程**
- **优先级**：P0
- **前置条件**：`/pool-a/to-sort/` 有 3 张 `jpg`；两个目标目录已建好。
- **步骤**：1) 点 `📂` → 进入 `/pool-a/to-sort/` → `选定此目录`；2) 点 `⚙ 设置` → 槽位 1 行点 `浏览` → 选 `/pool-a/target-a/` → `选定此目录`；3) `完成`；4) 点第 1 槽位 → 移动 1 张；5) 点 `↶ 撤销`。
- **预期结果（界面）**：步骤 2 后槽位 1 显示 `target-a`；步骤 4 后 toast `已移到「target-a」`、槽位 1 计数 `+1`、槽位闪光、主图变成下一张、`↶ 撤销` 出现上标计数 `1`；步骤 5 后主图跳回被撤销的那张、toast 形如 `已撤销：img-01.jpg → 第 1 / 3 张`。
- **预期结果（WebDAV 侧）**：步骤 4 后 `to-sort/` 少 1 张、`target-a/` 多 1 张；步骤 5 后恢复原状。
- **备注**：这是后续所有用例的基础操作路径。

**SMK-03 · WebDAV 不可达时不白屏**
- **优先级**：P0
- **前置条件**：能临时断开手机与 NAS 的网络（或停掉 WebDAV 服务）。
- **步骤**：1) 断网；2) 打开/刷新应用页面。
- **预期结果（界面）**：页面骨架完整渲染；底部弹出错误 toast（文案为 fetch 失败信息）；不会出现整页白屏或卡在 `载入中…`。
- **预期结果（WebDAV 侧）**：无。
- **备注**：`loadConfig` 与 `openSource` 各自 try/catch，错误走 toast。

## 7. 启动与配置（CFG）

**CFG-01 · 首次使用：NAS 上没有 `snap-config.json`**
- **优先级**：P0
- **前置条件**：删除 `/pool-a/snap-test/snap-config.json`；清空浏览器该站点的 `localStorage`。
- **步骤**：1) 打开页面；2) 观察主区与设置面板。
- **预期结果（界面）**：**没有**「配置读取失败」类错误提示（404 被静默处理）；源为空、20 个槽位全空、chip 显示 `图+视`；设置面板里「视频自动播放」= `开`、「自动全屏」= `关`。
- **预期结果（WebDAV 侧）**：`GET snap-config.json` 返回 404；此时应用**还没有**写任何文件（只有用户改动配置后才会 PUT）。
- **备注**：`loadConfig` 对 404 直接 `return false`，属于正常首次状态。

**CFG-02 · 有配置：NAS 上的配置生效并立即可用**
- **优先级**：P0
- **前置条件**：浏览器 `localStorage` 为干净状态；`snap-config.json` 里已写好：源 `/pool-a/to-sort/`、槽位 1 `/pool-a/target-a/`、chip `仅图片`。
- **步骤**：1) 打开页面；2) 观察顶栏/槽位/chip；3) 打开设置面板看「源」行与「媒体类型」分段按钮的高亮。
- **预期结果（界面）**：源按钮显示 `to-sort` 与其完整路径；槽位 1 显示 `target-a` 与计数；chip 显示 `仅图片`，设置面板里 `仅图片` 按钮为选中态；主图区显示 `to-sort/` 里的图片。
- **预期结果（WebDAV 侧）**：`snap-config.json` 内容未被改写（`updated` 时间戳不变）。
- **备注**：NAS 配置**覆盖**本地缓存（boot 先渲染缓存，再 `await loadConfig()` 覆盖）。

**CFG-03 · 配置读取失败 → 回退本地缓存**
- **优先级**：P0
- **前置条件**：先在正常环境打开一次页面并配好源与槽位（`localStorage['snap.config.cache']` 已有值）；然后让 `GET snap-config.json` 失败（断网，或把配置改成非法内容）。
- **步骤**：1) 刷新页面；2) 观察提示与槽位。
- **预期结果（界面）**：出现错误 toast，文案为 `配置读取失败（先用本地缓存）`；**槽位与源仍按本地缓存显示**（配置没丢）。
- **预期结果（WebDAV 侧）**：无写操作。
- **备注**：断网/JSON 解析失败都会抛错并进入该分支。

**CFG-04 · 配置读取返回非 200/404 的 HTTP 错误**
- **优先级**：P1
- **前置条件**：让 `GET snap-config.json` 返回 500（例如把该文件替换成应用无法读取的目录同名项，或用代理注入状态码；**需人工确认**可复现手段）。
- **步骤**：1) 打开页面。
- **预期结果（界面）**：弹出错误 toast `配置读取失败 HTTP 500（先用本地缓存）`。

## 10. 跨盘降级（XDS）

**XDS-01 · 同盘 MOVE 成功（不触发降级）**
- **优先级**：P0
- **前置条件**：源 `/pool-a/to-sort/`，目标 `/pool-a/target-a/`。
- **步骤**：1) 分类 1 张；2) 在 DevTools Network 里看请求。
- **预期结果（界面）**：toast `已移到「target-a」`（**没有**「跨盘复制」字样）。
- **预期结果（WebDAV 侧）**：只发出 `MOVE`（带 `Destination` 与 `Overwrite: F`），**没有** `COPY`/`DELETE`；源文件消失、目标出现。
- **备注**：同盘判定只看页面提示；实际是否降级由服务器对 MOVE 的响应决定。

**XDS-02 · 跨盘：MOVE 返回 405 → COPY + 校验 + DELETE**
- **优先级**：P0
- **前置条件**：源 `/pool-a/to-sort/`；槽位配 `/pool-b/target-x/`（**另一存储池**）。
- **步骤**：1) 点该槽位；2) 观察 Network 与最终状态。
- **预期结果（界面）**：toast 形如 `已移到「target-x」（跨盘复制）`；主图前进、槽位计数 +1。
- **预期结果（WebDAV 侧）**：请求顺序为 `MOVE`(405) → `COPY` → `PROPFIND`(目标, Depth 0) → `DELETE`(源)；最终源文件消失、目标文件大小与源一致。
- **备注**：405/502/500 都会被当作「无法 rename」进入降级分支。

**XDS-03 · 跨盘：复制后大小不一致 → 保留源文件并报错**
- **优先级**：P0
- **前置条件**：源有 1 张图片；能人为制造「COPY 成功但 `getcontentlength` 与源不同」的情形（例如在 COPY 与 PROPFIND 之间替换目标文件，或选一个会改写大小的目录配额场景）。**需人工确认**可复现手段。
- **步骤**：1) 移动到跨盘槽位。
- **预期结果（界面）**：toast 形如 `复制后大小不一致（源 12345 / 目标 6789）—— 已保留源文件，未删除`（错误色，5s）。当前张**仍在源目录**、列表不前进。
- **预期结果（WebDAV 侧）**：源文件**仍在**；目标目录里可能留有那份不一致的副本（应用不会自动删它）。
- **备注**：这是「宁可留垃圾也不丢文件」的安全兜底；测试需在一次性目录里做。撤销方向的**对称**校验（回拷大小不一致时保留目标位置的文件）见 UND-10。

**XDS-04 · 跨盘：`Overwrite: F` 同样生效（不覆盖目标同名文件）**
- **优先级**：P0
- **前置条件**：`/pool-b/target-x/` 已有 `img-01.jpg`（与源里同名、内容不同）。
- **步骤**：1) 跨盘分类 `/pool-a/to-sort/img-01.jpg` 到该槽位。
- **预期结果（界面）**：toast 显示已改名为 `img-01 (1).jpg`，并带 `（跨盘复制）`。
- **预期结果（WebDAV 侧）**：`target-x/img-01.jpg` 的**大小/内容与测试前一致**；新增 `img-01 (1).jpg`；源文件被删除。
- **备注**：COPY 与 MOVE 共用同一段「412 就换名」的重试逻辑。

**XDS-05 · 跨盘：COPY 失败（非 412）→ 明确报错、源文件不动**
- **优先级**：P1
- **前置条件**：让目标盘没有剩余空间或目标目录不可写（**需人工确认**可复现手段）。
- **步骤**：1) 跨盘分类。
- **预期结果（界面）**：toast 形如 `跨盘复制失败 HTTP 507（原 MOVE 返回 405）<服务器返回片段>`（括注里的状态码就是本次 `MOVE` 的返回码）；列表不前进、不产生撤销记录。
- **预期结果（WebDAV 侧）**：源文件仍在原位。
- **备注**：`place()` 在 `cp.ok === false` 时抛错，文案为 `跨盘复制失败 HTTP ${cp.status}（原 MOVE 返回 ${mv.status}）${body}`——**同时给出 COPY 的失败码与原始 MOVE 的返回码**，便于区分「真的是跨盘」还是「MOVE 被服务端错误地拒了」。

**XDS-06 · 跨盘：复制成功但删除源失败 → 双方都保留并告警**
- **优先级**：P1
- **前置条件**：能构造「DELETE 源返回非 204/200」的情形（**需人工确认**可复现手段，例如并发占用/只读源）。
- **步骤**：1) 跨盘分类。
- **预期结果（界面）**：toast 形如 `复制成功但删除源失败：目标已有副本、源仍在，请手动处理`（错误色）。
- **预期结果（WebDAV 侧）**：目标目录**有副本**、源目录**也有原件**（重复但不丢失）。
- **备注**：文案明确要求人工介入；用例结束需手动清理重复文件。

## 11. 撤销（UND）

**UND-01 · 单步撤销：文件回到原目录并跳回那一张**
- **优先级**：P0
- **前置条件**：源有 5 张；把 `img-01.jpg` 移到 `target-a`；当前显示第 1 张。
- **步骤**：1) 点 `↶ 撤销`（上标显示 `1`）。
- **预期结果（界面）**：先出现 `撤销中…`；随后 toast `已撤销：img-01.jpg → 第 1 / 5 张`（`撤销` 按钮回到置灰、无上标）；主图跳到 `img-01.jpg` 且胶片条里它被选中。
- **预期结果（WebDAV 侧）**：`MOVE`（`rec.from` → `backDir + rec.name`，`Overwrite: F`）；`to-sort/` 恢复 5 张、`target-a/` 少 1 张。
- **备注**：撤销后立即 `openSource(cwd, force=true)` 重扫目录，所以计数与条目数都会回到真实值。

**UND-02 · 多步撤销：连续撤销 3 步，每步都回到对应那张**
- **优先级**：P0
- **前置条件**：源有 5 张；依次把第 1 张移到 `target-a`、第 2 张移到 `target-b`、第 3 张移到 `target-a`。
- **步骤**：1) 连点 `↶ 撤销` 三次，每次记录 toast 里的文件名与「第 N / M 张」。
- **预期结果（界面）**：三次撤销的文件按**后进先出**顺序（第 3 张、第 2 张、第 1 张）；每次撤销后主图跳到被撤销的那张；按钮上标由 `3`→`2`→`1`→置灰；最后一次 toast 不再带「还可撤 N 步」。
- **预期结果（WebDAV 侧）**：5 张全部回到 `to-sort/`；两个目标目录恢复原状。
- **备注**：`undoStack` 是数组尾部为最新。

**UND-03 · 撤销的原子性：原位置已有同名文件 → 中止且不改动任何文件**
- **优先级**：P0
- **前置条件**：源有 `photo.jpg`，移到 `target-a` 后（可能已改名为 `photo (1).jpg`）；在 `to-sort/` 里手工放一个**同名**于 `rec.name` 的文件（即 `photo (1).jpg`）。
- **步骤**：1) 点 `↶ 撤销`。
- **预期结果（界面）**：toast `原位置已有同名文件，撤销中止（没有改动任何文件）`（错误色）；撤销栈**不变**（按钮上标仍是原数字）。
- **预期结果（WebDAV 侧）**：目标目录里的文件仍在原位；源目录里手工放的那个文件未被覆盖、大小不变。
- **备注**：靠 `Overwrite: F` 拿到 412；这条保证「宁可不撤销，也不覆盖」。

**UND-04 · 撤销时文件已不在原目标位置 → 跳过并弹掉这一步**
- **优先级**：P1
- **前置条件**：移动 2 张到 `target-a`；用文件管理器把**最近一次**移动的那个文件从 `target-a` 里删掉/改名。
- **步骤**：1) 点一次 `↶ 撤销`；2) 再点一次 `↶ 撤销`。
- **预期结果（界面）**：第一次 toast `这一步的文件已不在原目标位置（可能被别的程序移动过），已跳过`（警告色），撤销栈**减 1**（上标从 2 变 1）；第二次撤销正常成功。
- **预期结果（WebDAV 侧）**：被删的那个文件不会复现；第二个文件回到源目录。
- **备注**：`gone=true` 时 `dropUndo(rec)`，避免坏记录卡住后面几十步。

**UND-05 · 撤销恢复的是「移动后的名字」**
- **优先级**：P1
- **前置条件**：`target-a/` 已有 `photo.jpg`；源里的 `photo.jpg` 被移动后改名为 `photo (1).jpg`。
- **步骤**：1) 点 `↶ 撤销`。
- **预期结果（界面）**：toast `已撤销：photo (1).jpg → 第 … 张`。
- **预期结果（WebDAV 侧）**：源目录里出现的是 `photo (1).jpg`（**不是** `photo.jpg`）。
- **备注**：撤销记录存的是 `finalName`，不还原原始文件名。

**UND-06 · 刷新页面后仍可撤销（撤销栈持久化在 NAS）**
- **优先级**：P0
- **前置条件**：移动 2 张到不同目标目录。
- **步骤**：1) 硬刷新页面（或换一台设备打开同一地址）；2) 等页面加载完成；3) 观察 `↶ 撤销` 按钮；4) 点一次撤销。
- **预期结果（界面）**：刷新后按钮上标直接显示 `2`（无需先做任何操作）；撤销成功且 toast 正常。
- **预期结果（WebDAV 侧）**：`snap-config.json` 的 `undo` 数组在移动后即被写入（含 `backDir`/`name`/`from`）；撤销后数组长度减 1 并回写。
- **备注**：`snapshot()` 里 `undo: S.undoStack.slice(-50)`。

**UND-07 · 跨盘移动的撤销同样走 COPY+校验+DELETE**
- **优先级**：P0
- **前置条件**：把源里 1 张图跨盘移到 `/pool-b/target-x/`（toast 带「跨盘复制」）。
- **步骤**：1) 点 `↶ 撤销`；2) 看 Network。
- **预期结果（界面）**：toast `已撤销：<文件名> → 第 … 张`。
- **预期结果（WebDAV 侧）**：回程同样是 `MOVE`(405) → `PROPFIND`(目标位置，记下原大小) → `COPY` → `PROPFIND`(源位置) → `DELETE`(目标副本)；最终文件回到源目录、跨盘副本消失。
- **备注**：回拷会**先记下 `rec.from` 的大小**、回拷后再比对（见 UND-10）：`!info || info.dir` → `回拷校验失败 —— 原副本仍在目标位置，未删除`；大小不一致 → `回拷后大小不一致（原 X / 新 Y）—— 目标位置的文件已保留，未删除`；只有校验通过才 `DELETE` 目标位置的副本。与 `place()` 的跨盘路径完全对称。

**UND-08 · 撤销栈 50 步上限**
- **优先级**：P2
- **前置条件**：准备一份 `snap-config.json` 变体，其 `undo` 数组含 **55 条**合法记录（字段齐全）。
- **步骤**：1) PUT 该配置；2) 刷新页面；3) 读撤销按钮上标；4) GET 一次配置。
- **预期结果（界面）**：上标显示 `50`（只保留**最后 50 条**，最早 5 条被丢弃）。
- **预期结果（WebDAV 侧）**：回写后 `undo` 长度为 50。
- **备注**：连续真实移动 51 次也能验证（耗时长，可选）；`classify` 里 `push` 后立即 `shift`。

**UND-09 · 没有可撤销操作时的表现**
- **优先级**：P2
- **前置条件**：撤销栈为空（新配置或刚全部撤销完）。
- **步骤**：1) 观察按钮；2) 桌面浏览器按 `Ctrl+Z`。
- **预期结果（界面）**：按钮置灰（`disabled`，透明度降低）；`Ctrl+Z` 时 toast `没有可撤销的操作`（警告色），无任何文件变化。
- **预期结果（WebDAV 侧）**：无写请求。
- **备注**：快捷键路径不做 `disabled` 拦截，靠内部判断。

**UND-10 · 跨盘撤销：回拷后大小不一致 → 保留目标位置的文件并报错**
- **优先级**：P1
- **前置条件**：把源里 1 张图跨盘移到 `/pool-b/target-x/`（撤销栈 1 条，`rec.from` 指向 `target-x` 里的副本）；需要人为制造「COPY 回拷成功但大小与回拷前的 `rec.from` 不一致」的情形（例如在 COPY 与 `PROPFIND` 之间替换源位置的目标文件，或使用会改写大小的存储场景）。**需人工确认**可复现手段。
- **步骤**：1) 点 `↶ 撤销`。
- **预期结果（界面）**：toast 形如 `回拷后大小不一致（原 12345 / 新 6789）—— 目标位置的文件已保留，未删除`（错误色，5s）；列表不前进、不跳回；**撤销栈仍保留这一步**（按钮上标不变，可重试或人工处理）。
- **预期结果（WebDAV 侧）**：源目录里出现的是那份**大小不一致**的回拷副本；`/pool-b/target-x/` 里的原副本**仍在**（没有执行 `DELETE`）——也就是「宁可留两份，也不丢文件」。
- **备注**：这是本轮新增的对称校验：`undo()` 在 `MOVE` 得到 405/502/500 时会先 `statOf(rec.from)` 记下 `before.size`，回拷后比对 `info.size`；`before.size > 0` 才比较（服务器不返回大小则不误报）。与 `place()` 的跨盘校验（XDS-03）对应。

**FLT-06 · 切换筛选后不出现「已移走的文件」（幽灵条目）**

**SLT-12 · 源与目标互换（含无源时提升为目标）**

**DEL-02 · 含非媒体文件（txt 等）被拒绝：不出现删除入口**

- **预期结果（界面）**：全屏**可以**正常进入（Fullscreen API 不要求安全上下文）；但**无法**做成无地址栏的独立 PWA 窗口（安装入口不可用或退化成普通书签）。
- **预期结果（WebDAV 侧）**：无。
- **备注**：代码注释明确：`"像 App 一样独立窗口、无地址栏" 的 PWA 安装必须要 HTTPS + Service Worker`。若要用这个能力，需给 WebDAV 前置 HTTPS 反代（本仓库的部署脚本只做 HTTP PUT，不涉及 HTTPS 配置）。

## 18. 异常与恢复（ERR）

**ERR-01 · 认证失败（PROPFIND 401）**
- **优先级**：P0
- **前置条件**：把浏览器缓存的该 origin 凭据改错，或清掉凭据后输入错误密码；然后触发一次列目录（打开页面或点 `↻`）。
- **步骤**：1) 打开页面（无配置时 `openSource` 会列目录）。
- **预期结果（界面）**：toast `认证失败：重新输入 NAS 账号密码后刷新页面`（错误色，5s）；页面骨架仍在，不会白屏。
- **预期结果（WebDAV 侧）**：`PROPFIND` 返回 401。
- **备注**：应用**没有**自己的登录界面，靠浏览器凭据；提示语明确要求刷新页面。

**ERR-02 · 认证失败时读取配置**
- **优先级**：P1
- **前置条件**：同上（凭据无效），且 `snap-config.json` 存在。
- **步骤**：1) 刷新页面；2) 观察 toast 序列。
- **预期结果（界面）**：出现 `配置读取失败 HTTP 401（先用本地缓存）`；若本地有缓存，则槽位/源仍按缓存显示。
- **预期结果（WebDAV 侧）**：`GET snap-config.json` 返回 401。
- **备注**：401 不属于 404 分支，因此会被当成错误并提示。

**ERR-03 · 源目录不存在（被外部删除/改名）**
- **优先级**：P1
- **前置条件**：配置里 `source` 指向 `/pool-a/to-sort/`；从外部把该目录改名或删掉。
- **步骤**：1) 刷新页面。
- **预期结果（界面）**：toast `目录不存在`（错误色）；页面其余部分正常（槽位仍按配置显示）；`↶ 撤销` 仍可用（若栈非空）。
- **预期结果（WebDAV 侧）**：对源路径 `PROPFIND` 返回 404。
- **备注**：`openSource()` 中 `if (!list) throw new Error('目录不存在')`。

**ERR-04 · 断网 / WebDAV 服务不可达**
- **优先级**：P0
- **前置条件**：页面已加载出内容；断开网络（或停掉 WebDAV 服务）。
- **步骤**：1) 点一个已配置的槽位分类当前张；2) 再点 `↶ 撤销`。
- **预期结果（界面）**：分类与撤销各自弹出错误 toast（内容为 fetch 失败信息，`TypeError: Failed to fetch` 之类）；**当前张仍停在原处**、列表不前进、撤销栈不减少。
- **预期结果（WebDAV 侧）**：无请求成功。
- **备注**：`place()` 的网络异常会冒泡到 `classify` 的 catch（`e.status` 非 404 → 走通用错误分支）。

**ERR-05 · 移动中源文件消失（404）→ 自动摘除该条目**
- **优先级**：P0
- **前置条件**：源目录有 3 张图，当前停在第 1 张；**在别处**（文件管理器/另一台设备）把这张图移走或改名。
- **步骤**：1) 点槽位 1 分类当前张。
- **预期结果（界面）**：toast `这个文件已不在源目录，已从列表移除`（警告色，4s）；该图**从列表与胶片条消失**；主图变成下一张（列表长度减 1）；槽位计数**不增加**。
- **预期结果（WebDAV 侧）**：`MOVE` 返回 404；目标目录无新文件。
- **备注**：只有 `e.status === 404` 才走这条分支（`place()` 会把 MOVE 的状态码挂在 error 上）。

**ERR-06 · 目标目录在移动前被删除**
- **优先级**：P1
- **前置条件**：槽位 1 指向 `/pool-a/target-a/`；从外部把该目录删掉（配置未变）。
- **步骤**：1) 点槽位 1 分类。
- **预期结果（界面）**：toast 形如 `移动失败 HTTP 404 <服务器返回片段>` 或 `移动失败 HTTP 409 ...`（取决于服务器对不存在的 Destination 的响应，**需人工确认**）；当前张仍在源目录、列表不前进。
- **预期结果（WebDAV 侧）**：源文件未被删除（MOVE 失败时不会走 COPY 分支，因为状态码不是 405/502/500）。
- **备注**：这正是「先 MOVE 失败再说」的安全点；若服务器用 500 表示目标不存在，则会误入跨盘降级（见 ERR-07）。

**ERR-07 · MOVE 返回 405/500/502 一律降级为 COPY+校验+DELETE（设计选择，需验证数据完好）**
- **优先级**：P1
- **前置条件**：源与目标**在同一块盘**（例如源 `/pool-a/to-sort/`、槽位 1 = `/pool-a/target-a/`）；让服务器对该次 `MOVE` 返回 500 或 502（服务端异常；**需人工确认**可复现手段，例如临时反代改写状态码）。
- **步骤**：1) 分类当前张；2) 在 DevTools Network 里看请求序列；3) 用 `PROPFIND`/哈希比对源与目标文件；4) 点一次 `↶ 撤销`。
- **预期结果（界面）**：不会弹「移动失败」类错误；降级成功后 toast 带 `（跨盘复制）`（**即使实际同盘**，文案也按降级路径显示）；列表前进、槽位计数 +1、`↶ 撤销` 上标 +1；第 4 步能正常撤销回源目录。
- **预期结果（界面 · 降级也失败时）**：若 `COPY` 也没成功，toast 形如 `跨盘复制失败 HTTP <COPY 的状态码>（原 MOVE 返回 <MOVE 的状态码>）<服务器返回片段>`——**两个状态码都要出现**，据此可以判断是「跨盘」还是「MOVE 本身被误拒」。此分支下列表不前进、不产生撤销记录、源文件保留。
- **预期结果（WebDAV 侧）**：请求序列为 `MOVE`(500/502) → `COPY` → `PROPFIND`(Depth 0，目标) → `DELETE`(源)；最终源目录少 1 个文件、目标目录多 1 个**大小一致**的文件（有条件时比对内容哈希），**数据完好**。
- **备注（设计选择 + 安全理由）**：把 `405 / 500 / 502` 都视为「服务器不能 rename」是**有意的**——这类 NAS 的 WebDAV 在跨挂载点 `MOVE` 时会返回 405，而部分服务端在跨盘时用 500/502 表达同一件事。降级路径本身是安全的：`COPY → 校验目标存在且大小一致 → 才 DELETE 源`，任何一步不满足都**保留源文件**并报错（见 XDS-03 / XDS-05 / XDS-06），因此这条降级路径**不会丢数据**；代价是极端情况下多一次拷贝。
- **备注（可读性建议已采纳）**：此前降级失败的提示只说 `跨盘复制失败 HTTP <code>`，当 500/502 其实与「不能 rename」无关（目标目录不存在、权限不足等）时容易误导排查；现在失败文案里**已补上原 MOVE 的返回码**（`（原 MOVE 返回 <code>）`，见 XDS-05），本用例的失败分支预期也据此断言。

**ERR-08 · 列目录返回非 207**
- **优先级**：P2
- **前置条件**：让 `PROPFIND` 返回 403/500（**需人工确认**可复现手段）。
- **步骤**：1) 打开页面或点目录浏览器里的 `↻`。
- **预期结果（界面）**：toast `列目录失败 HTTP <code>`（错误色）；目录浏览器里显示红色错误说明行（`pickerLoad` 的 catch 分支）；已加载的主区内容不被清空。
- **预期结果（WebDAV 侧）**：一次失败的 `PROPFIND`。
- **备注**：`propfind()` 只接受 207，其它状态（除 401/404）统一报错。

- **优先级**：P0
- **前置条件**：源目录有图片、槽位 1 已配置、撤销栈非空。
- **步骤**：1) 打开 `⚙ 设置`，依次按 `→`、`空格`、`1`、`Ctrl+Z`；2) 按 `Esc`；3) 打开目录浏览器，重复步骤 1 的按键，再按 `Esc`；4) 从设置面板里点槽位 `浏览` 打开目录浏览器，按 `Esc`。
- **预期结果（界面）**：面板打开期间**所有**这些快捷键都无效（不翻页、不分类、不撤销、无 toast，`preventDefault` 也不影响）；`Esc` 分别关闭设置面板、关闭目录浏览器；步骤 4 里目录浏览器用 `Esc` 关闭后**退回设置面板**（与点 `✕`/`取消` 一致）；关闭后面板外的快捷键恢复正常。
- **预期结果（WebDAV 侧）**：屏蔽期间**没有**任何写请求。
- **备注**：`keydown` 首行统一判断 `gridSheet` / `browseSheet` / `setupSheet` 三者是否 `on`，是则只处理 `Escape` 然后 `return`。

**KBD-06 · 图集打开时快捷键同样被屏蔽（已修回归项）**
- **优先级**：P0
- **前置条件**：图集已打开（用 `→` 之类的按键之外的方式打开，确保焦点在页面上），撤销栈非空，槽位 1 已配置。
- **步骤**：1) 按 `1`；2) 按 `Ctrl+Z`/`Cmd+Z`；3) 按 `→`；4) 按 `Esc`；5) 再按 `1`。
- **预期结果（界面）**：步骤 1–3 **全部无效**——不会移动文件、不会撤销、不会翻页，也没有 toast；图集保持打开、选中框不变；步骤 4 `Esc` 关闭图集；步骤 5 此时 `1` 恢复生效（真的把当前张移到槽位 1）。
- **预期结果（WebDAV 侧）**：步骤 1–3 期间**没有**任何写请求；步骤 5 产生一次真实的 `MOVE`。
- **备注**：这是本轮修复的**回归重点**——此前屏蔽名单漏了 `gridSheet`，图集开着按 `1-9` 会真的把文件移走。修复后 `keydown` 的屏蔽名单同时包含 `gridSheet`、`browseSheet`、`setupSheet`，并在面板打开时只响应 `Escape`。

**KBD-07 · 窗口缩放 / 屏幕旋转**
- **优先级**：P2
- **前置条件**：桌面浏览器；槽位区已配置 20 个目录（内容高度超过 3 行）。
- **步骤**：1) 把窗口高度缩小再放大；2) 把槽位区滚到底部；3) 再滚动回顶部；4) 旋转手机屏幕（横竖切换）。
- **预期结果（界面）**：底部渐隐提示随内容是否溢出而显隐（滚到底部时渐隐**消失**）；**滚动位置不会因为移动文件而跳回顶部**（槽位按钮是原地更新，不重建 DOM）；手机旋转后布局自适应，渐隐状态被重新计算（`resize` 监听）。
- **预期结果（WebDAV 侧）**：无。
- **备注**：`updateSlotsFade()` 在初始渲染、滚动、移动后、`resize` 时都会调用。

## 21. 执行顺序建议

### 阶段 A · 冒烟（约 15 分钟）
1. `SMK-01` 页面加载骨架
2. `SMK-02` 完整主流程（选源 → 配一个槽位 → 移动 → 撤销）
3. `SMK-03` 断网不白屏
4. `CFG-01` 首次无配置

> 冒烟不通过就不要往下做：后面的用例全都依赖「能选源、能配置、能移动」。

### 阶段 B · 主流程与非破坏性功能（约 1.5 小时）
5. 配置相关：`CFG-02` → `CFG-10`（其中的清理类 `CFG-06`/`CFG-07` 要改配置，做完立刻恢复）
6. 浏览与选源：`NAV-01` … `NAV-10`
7. 筛选与排序：`FLT-01` … `FLT-08`
8. 图集：`GRD-01` … `GRD-09`
9. 槽位配置：`SLT-01` … `SLT-12`
10. 视频与全屏：`VID-01` … `VID-06`、`FS-01` … `FS-06`（自动播放/自动全屏的开关记得改回默认）
11. 桌面兼容：`KBD-01` … `KBD-07`

### 阶段 C · 破坏性 / 边界（约 1.5 小时，只在一次性目录里做）
12. 分类与撤销（会产生真实文件移动）：`MOV-01` … `MOV-10` → `UND-01` … `UND-10`
13. 跨盘：`XDS-01` … `XDS-06`（需要 `pool-b` 上的可丢弃目录）
14. 删除空目录：`DEL-01` … `DEL-08`（**务必确认目标目录是可丢弃的**）
15. 异常：`ERR-01` … `ERR-08`（多数需要人为制造故障，建议放在最后，避免影响前面的环境；`ERR-07` 需验证降级后数据完好）
16. 边界：`EDG-01` … `EDG-09`

### 阶段 D · 回归
- 每次改动 `public/index.html` 后，至少重跑：`SMK-01`~`SMK-03`、`MOV-01`、`MOV-02`、`FLT-06`、`UND-06`、`DEL-04`、`DEL-05`、`XDS-02`、`SLT-08`、`SLT-10`、`KBD-05`、`KBD-06`、`ERR-07`。
- 这几条覆盖了历史上出现过的坑：已移走文件「复活」、删除入口不出现、撤销栈不持久、跨盘丢文件、**图集打开时误移文件**、**批量添加绕过源/丢弃互斥**、**全部清空未清撤销栈**、**跨盘降级被误判为丢数据**。

## 22. 清理步骤

测试结束后按顺序执行（**全部完成前不要把测试目录留给别人用**）：

1. **停用应用**：关闭所有打开了测试地址的标签页（避免它继续往 `snap-config.json` 写）。
2. **恢复配置**：
   - 若测试前有备份：把备份**原样 PUT 回** `/pool-a/snap-test/snap-config.json`；PUT 后 GET 一次确认内容与备份一致。
   - 若测试前没有配置：直接 `DELETE /pool-a/snap-test/snap-config.json`，让环境回到「首次使用」状态。
3. **清空本地偏好**（可选，测「首次使用」时必做）：在浏览器里清掉该站点的 `localStorage`（键 `snap.config.cache`、`snap.filter`、`snap.autoplay`、`snap.autofs`、`snap.sort`）。
4. **归还测试文件**：把 `/pool-a/target-a/`、`/pool-a/target-b/`、`/pool-a/target-c/`、`/pool-b/target-x/`、`/pool-a/discard/` 里的测试文件回收到 `/pool-a/to-sort/`（或直接连同目录一起删掉，因为都是一次性目录）。
5. **删除一次性目录**：`/pool-a/to-sort/`、`/pool-a/target-a/`、`/pool-a/target-b/`、`/pool-a/target-c/`、`/pool-a/discard/`、`/pool-b/target-x/`、`/pool-a/empty-src/`、`/pool-a/中文 目录/`、`/pool-a/emoji-🎞️/` 等用例目录。
6. **删除测试部署**：`DELETE /pool-a/snap-test/index.html`；确认 `/pool-a/snap-test/` 已空后删掉该目录。
7. **复核**：确认没有任何真实工作目录被移动/删除了内容（可用 NAS 的回收站或文件管理器核对 `target-*` 与 `to-sort` 的原始内容），确认 `.nas-cred` 等本地凭据文件没有进入版本库（`git status` 应为干净，除本文件所在的 `tests/` 目录外无改动）。
8. **记录**：把本次执行结果（通过/失败/阻塞 + 版本/机型/浏览器版本）记在测试记录里，失败的用例附上截图与 Network 请求序列。
